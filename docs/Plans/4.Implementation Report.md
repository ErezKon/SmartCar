## Sub-Plan 2: Backend - Charging Sessions Service, Alarm Poller & API Routes

**Status**: Completed

### Changes Made

#### 1. `backend/src/saic/charging-sessions.ts` (new file)

Service layer for charging session management.

**Constants & helpers**:
- `BATTERY_CAPACITY_KWH = 77` - MG4 X Range usable battery capacity
- `socToKwh(socPct)` - Converts SOC percentage to kWh

**Exported functions**:

| Function | Description |
|----------|-------------|
| `startChargingSession(vin)` | Guards against duplicate active sessions, live-fetches vehicle status + charging data to get SOC (raw * 0.1) and odometer (raw * 0.1), creates a new session via repository |
| `stopChargingSession(vin)` | Gets active session, live-fetches end SOC + odometer, calculates energy added, distance/energy since last completed session, efficiency (kWh/100km), completes session |
| `getChargingSessions(vin, limit, offset)` | Pass-through to repository for paginated listing |
| `getChargingStats(vin)` | Pass-through to repository for aggregate stats |
| `getActiveChargingSession(vin)` | Returns the active session for a VIN (if any) |
| `deleteChargingSession(id)` | Pass-through to repository for deletion |

**Key implementation details**:
- Uses `Promise.all` for parallel live-fetch of vehicle status and charging data
- Catches individual fetch errors with warnings (doesn't fail silently but logs)
- Efficiency calculation only occurs when distance > 0 and energy used > 0
- Custom `statusCode` property on errors (409 for duplicate session, 404 for no active session)

#### 2. `backend/src/saic/alarm-poller.ts` (new file)

Background alarm message poller for auto-detecting charging events.

**Exported functions**:
- `startAlarmPoller()` - Starts polling every 60s with 10s initial delay
- `stopAlarmPoller()` - Stops the interval

**Internal functions**:
- `isChargingStartAlarm(msg)` - Pattern-matches alarm messages for charging start (checks title, content, messageType for keywords like "charg" + "start"/"begin")
- `isChargingStopAlarm(msg)` - Pattern-matches for charging stop (keywords: "stop", "end", "complete", "finish")
- `processAlarmMessages(messages)` - Sorts by messageId, skips already-processed, logs all alarms at DEBUG level for format discovery, triggers start/stop charging sessions
- `pollAlarms()` - Single-flight guard, checks if SAIC account exists before polling, calls `getMessages('ALARM')`, processes results

**Key implementation details**:
- Tracks `lastProcessedMessageId` in memory to avoid duplicate processing
- Silently skips when no SAIC account is connected (logs at DEBUG, not ERROR)
- Auth errors are logged as DEBUG-level (account might not be set up yet)
- Messages sorted ascending by messageId to process in chronological order
- Guards against starting a session when one is already active, and stopping when none is active

#### 3. `backend/src/routes/saic.routes.ts`

**New import**: `charging-sessions` module (startChargingSession, stopChargingSession, getChargingSessions, getChargingStats, getActiveChargingSession, deleteChargingSession)

**5 new route handlers added** (between Messages and Commands sections):

| Method | Path | Rate Limiter | Description |
|--------|------|-------------|-------------|
| `POST` | `/vehicles/:vin/charging-sessions/start` | refreshLimiter | Creates a new charging session, returns 201 with session data |
| `POST` | `/vehicles/:vin/charging-sessions/stop` | refreshLimiter | Completes active session with calculated stats |
| `GET` | `/vehicles/:vin/charging-sessions` | none | Lists sessions (paginated), includes `hasActiveSession` boolean |
| `GET` | `/vehicles/:vin/charging-sessions/stats` | none | Returns aggregate statistics |
| `DELETE` | `/vehicles/:vin/charging-sessions/:id` | none | Deletes a session by ID, validates ID is numeric |

**Error handling**: All routes use `safeErrorMessage()` for redacting sensitive info, custom `statusCode` from service errors (409, 404) propagated to HTTP response.

#### 4. `backend/src/server.ts`

- Added `import { startAlarmPoller, stopAlarmPoller }` from alarm-poller
- Added `startAlarmPoller()` call after `startSaicPolling()` in startup sequence
- Added `stopAlarmPoller()` call in graceful shutdown handler (before `stopNgrokTunnel()`)

## Sub-Plan 3: Frontend - Models, API Service & Dashboard Buttons

**Status**: Completed

### Changes Made

#### 1. `frontend/src/app/core/models/saic.models.ts`

**New interfaces added**:

- `SaicChargingSession` - Mirrors backend model with all fields: id, vin, status, start/end times, SOC, battery kWh, energy added, odometer, distance/energy since last charge, efficiency, created_at. Proper nullability for optional end-state fields.
- `SaicChargingStats` - Aggregate statistics: total_sessions, total_energy_added_kwh, total_distance_tracked_km, average/best/worst efficiency (nullable for cases with no data)

#### 2. `frontend/src/app/core/services/saic-api.service.ts`

**New import**: `SaicChargingSession`, `SaicChargingStats` from models

**5 new API methods added**:

| Method | HTTP | Endpoint | Return Type |
|--------|------|----------|-------------|
| `startChargingSession(vin)` | POST | `/api/saic/vehicles/:vin/charging-sessions/start` | `{ data: SaicChargingSession }` |
| `stopChargingSession(vin)` | POST | `/api/saic/vehicles/:vin/charging-sessions/stop` | `{ data: SaicChargingSession }` |
| `getChargingSessions(vin, limit?, offset?)` | GET | `/api/saic/vehicles/:vin/charging-sessions` | `{ data: SaicChargingSession[]; hasActiveSession: boolean }` |
| `getChargingStats(vin)` | GET | `/api/saic/vehicles/:vin/charging-sessions/stats` | `{ data: SaicChargingStats }` |
| `deleteChargingSession(vin, id)` | DELETE | `/api/saic/vehicles/:vin/charging-sessions/:id` | `{ status: string }` |

#### 3. `frontend/src/app/features/saic/saic-dashboard.component.ts`

**New properties**:
- `hasActiveChargingSession: boolean` - Tracks whether a session is currently active (controls button enabled/disabled state)
- `logChargeStartStatus: CmdStatus` - Loading/success/error state for the start button
- `logChargeStopStatus: CmdStatus` - Loading/success/error state for the stop button

**New methods**:
- `checkActiveChargingSession()` - Queries the backend for active sessions on the selected VIN, called after signals load
- `logChargeStart()` - Calls `startChargingSession()`, sets `hasActiveChargingSession = true` on success, shows snackbar
- `logChargeStop()` - Calls `stopChargingSession()`, sets `hasActiveChargingSession = false` on success, shows snackbar

**Modified**: `loadSignals()` - Added `this.checkActiveChargingSession()` call in the success handler to check session state whenever signals are loaded

#### 4. `frontend/src/app/features/saic/saic-dashboard.component.html`

**Added to Battery & Charging card** (after the existing Start/Stop Charge command buttons):
- `<mat-divider>` separator
- "Session Logging" section with label and two buttons:
  - "Log Charge Start" button - primary color, play_arrow icon, disabled when active session exists or loading, with tooltip explaining its purpose
  - "Log Charge Stop" button - accent color, stop_circle icon, disabled when no active session or loading, with tooltip

Both buttons use the existing `app-command-button` shared component with `disabled` input binding.

## Sub-Plan 4: Frontend - Statistics Page & Sidebar Navigation

**Status**: Completed

### Changes Made

#### 1. `frontend/src/app/features/saic/saic-statistics.component.ts` (new file)

Standalone Angular component for the Statistics page.

**Properties**:
- `vehicles` / `selectedVin` - Vehicle selection (same pattern as dashboard)
- `sessions: SaicChargingSession[]` - All charging sessions for the selected VIN
- `stats: SaicChargingStats | null` - Aggregate statistics
- `sessionsLoading` / `loading` / `error` - Loading and error state
- `sessionColumns` - Table column definitions: date, soc, energy_added, distance, efficiency, actions

**Methods**:

| Method | Description |
|--------|-------------|
| `loadVehicles()` | Loads vehicle list, auto-selects first VIN, triggers data load |
| `onVehicleChange()` | Reloads data when vehicle selection changes |
| `loadData()` | Parallel fetch of sessions and stats for the selected VIN |
| `deleteSession(session)` | Deletes a session, removes from local array, reloads stats |
| `formatDate(dateStr)` | Formats ISO date to human-readable format (DD Mon YYYY HH:MM) |
| `formatNum(val, decimals)` | Formats number with fixed decimals, returns '-' for null |

**Computed properties**:
- `completedSessions` - Filters sessions to status='completed' only
- `sessionsWithEfficiency` - Completed sessions that have efficiency data
- `efficiencyTrend` - Array of { date, efficiency } for the bar chart, ordered chronologically

**Key implementation details**:
- Follows the same standalone component pattern as the dashboard (imports, DI, subscriptions)
- Uses `SaicApiService` for all data fetching
- Vehicle selector shown only when multiple vehicles exist (same as dashboard)

#### 2. `frontend/src/app/features/saic/saic-statistics.component.html` (new file)

**Template sections**:

1. **Header** - Page title with bar_chart icon, vehicle selector (when > 1 vehicle), refresh button
2. **Summary cards grid** - 6 cards showing: Total Sessions, Energy Added (kWh), Distance Tracked (km), Avg Efficiency (kWh/100km), Best Efficiency, Worst Efficiency. Each card has a colored icon circle and value/label.
3. **Efficiency trend card** - Bar chart visualization showing efficiency across sessions. Bars are color-coded: green for best, red for worst, purple for others. Height proportional to the worst efficiency value. Tooltips show exact values.
4. **Sessions table card** - Full table with columns: Date (with status chip), SOC (start -> end), Energy Added (kWh), Distance Driven (km), Efficiency (kWh/100km with color coding: green <= 16, yellow 16-20, red > 20), Delete button. Empty state with instructions when no sessions exist.

#### 3. `frontend/src/app/features/saic/saic-statistics.component.scss` (new file)

**Styles**:
- `.statistics-container` / `.statistics-header` - Page layout matching dashboard pattern
- `.summary-grid` - CSS grid with auto-fill columns (min 220px)
- `.summary-card` - Flex row with icon circle and data column
- `.summary-icon` variants - 6 color themes (sessions=indigo, energy=green, distance=blue, efficiency=orange, best=teal, worst=red)
- `.trend-card` / `.trend-bars` - Flex container for bar chart with overflow-x scroll
- `.trend-bar` - Colored bars with height transition, best/worst color overrides
- `.sessions-card` / `.sessions-table` - Table styles with overflow wrapper
- `.status-chip` - Inline status badge (blue for active, green for completed)
- `.efficiency-value` - Color-coded text (green/yellow/red based on value)
- `.empty-state` - Centered message with large icon for no-data state
