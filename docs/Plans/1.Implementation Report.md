## Sub-Plan 2: Authentication & Token Management - COMPLETED

### Summary
Implemented OAuth 2.0 client credentials flow with token caching and auto-refresh, Smartcar Connect vehicle authorization flow, auth routes, and auth middleware.

### Changes Made

#### 1. Token Manager (`backend/src/auth/token-manager.ts`)
- `getAccessToken()` - Returns cached token from SQLite or fetches new one
- `fetchNewToken()` - POST to `https://iam.smartcar.com/oauth2/token` with Basic auth (client_id:client_secret base64), `grant_type=client_credentials`
- Token cached in SQLite with expiry tracking (refreshes 10 min before expiry)
- Concurrent request deduplication via shared promise (prevents multiple simultaneous token refreshes)
- `forceTokenRefresh()` - Manual token refresh, clears existing cache
- `getTokenInfo()` - Returns token status without exposing the actual token value

#### 2. Base HTTP Client (`backend/src/api/client.ts`)
- `SmartcarClient` class wrapping Node.js native `fetch()`
- Auto-attaches `Authorization: Bearer {token}` header via `getAccessToken()`
- Auto-attaches `sc-user-id` header when userId provided
- Handles rate limiting (429) with `retry-after` header support
- Automatic retry with exponential backoff (3 retries max)
- Parses JSON:API error responses into typed `SmartcarApiError`
- Supports both Vehicle API and Management API base URLs via `base` parameter
- Supports raw URLs for compatibility API (no auth)
- Convenience methods: `get()`, `post()`, `delete()`

#### 3. Smartcar Connect Flow (`backend/src/auth/connect.ts`)
- `buildConnectUrl(options)` - Constructs the Connect authorization URL with parameters:
  - `application_id`, `redirect_uri`, `response_type` (code/none), `mode` (simulated/live)
  - Optional: `scope`, `state`, `make`, `single_select`, `single_select_vin`, `external_id`, `flags`
- `handleConnectCallback(queryParams)` - Processes the Connect redirect response:
  - Extracts `user_id`, stores in SQLite via `UserRepository`
  - Handles error responses (`access_denied`, `vehicle_incompatible`, etc.) via `ConnectFlowError`

#### 4. Auth Routes (`backend/src/routes/auth.routes.ts`)
- `GET /auth/connect` - Redirects user to Smartcar Connect (supports query params: mode, make, single_select, state)
- `GET /auth/callback` - Handles Connect redirect, stores user_id, redirects to frontend with status
- `GET /auth/status` - Returns current auth status: token info + connected users list
- `POST /auth/token` - Manually triggers token refresh, returns new token info (preview only)
- `GET /auth/token` - Returns current token info (hasToken, expiresAt, remainingSeconds)

#### 5. Auth Middleware (`backend/src/middleware/auth.middleware.ts`)
- `ensureAuthenticated` - Middleware that ensures a valid access token exists before proxying to Smartcar API
- `extractUserId` - Middleware that extracts `sc-user-id` from request header or `userId` query parameter, attaches to request object

## Sub-Plan 3: Connections & Vehicle Data API - COMPLETED

- `GET /api/connections/:connectionId` - Get single connection, caches locally
- `DELETE /api/connections/:connectionId` - Remove connection from Smartcar + local cache
- `DELETE /api/connections/users/:userId` - Remove user and all connections from Smartcar + local cache

- All signal reads (list and individual) automatically saved to `signal_snapshots` table

- Connection data cached in `connections` table on fetch
- Signal history queryable via `/signals-history` endpoint

## Sub-Plan 5: Management API, Webhooks & Compatibility - COMPLETED

### Summary
Implemented the Management API (applications, secrets, webhooks, subscriptions), a webhook receiver with HMAC-SHA256 signature verification, ngrok tunnel support for development, and the Compatibility API with 24-hour caching.

### Changes Made

#### 1. Management API Client (`backend/src/api/management.ts`)
- **Applications**:
  - `listApplications()` - GET `/applications` (Management API)
  - `getApplication(applicationId)` - GET `/applications/{applicationId}`
  - `getApplicationSecrets(applicationId)` - GET `/applications/{applicationId}/secrets`
- **Webhooks**:
  - `listWebhooks()` - GET `/webhooks` (Management API)
  - `getWebhook(webhookId)` - GET `/webhooks/{webhookId}`
- **Subscriptions**:
  - `listSubscriptions(filters?, pagination?)` - GET `/subscriptions` with query params: `filter[webhookId]`, `filter[vehicleId]`, `filter[userId]`, `page[number]`, `page[size]`
  - `createSubscription(webhookId, userId, vehicleId)` - POST `/subscriptions` with JSON:API body
  - `getSubscription(subscriptionId)` - GET `/subscriptions/{subscriptionId}`
  - `removeSubscription(subscriptionId)` - DELETE `/subscriptions/{subscriptionId}`
- Typed interfaces: `Application`, `ApplicationSecret`, `Webhook`, `Subscription`, list/detail response types, `SubscriptionFilters`, `PaginationOptions`

#### 2. Webhook Verification Middleware (`backend/src/middleware/webhook-verification.ts`)
- HMAC-SHA256 signature verification using `SC-Signature` header
- Uses `SMARTCAR_APP_MANAGEMENT_TOKEN` as the HMAC secret key
- Timing-safe comparison via `crypto.timingSafeEqual` to prevent timing attacks
- Validates signature presence and format before processing

#### 3. Webhook Routes (`backend/src/routes/webhooks.routes.ts`)
- **Webhook Receiver** (public, verified by signature):
  - `POST /webhooks/receive` - Main webhook receiver endpoint
    - Verifies HMAC-SHA256 signature
    - Handles `VERIFY` events (returns challenge response)
    - Handles `VEHICLE_STATE` events (stores signals in SQLite via `SignalRepository`)
    - Handles `VEHICLE_ERROR` events (logs and stores)
    - Unknown event types acknowledged and stored
- **Management Webhook Routes** (require auth):
  - `GET /api/webhooks` - List configured webhooks from Management API
  - `GET /api/webhooks/:webhookId` - Get webhook details
- **Subscription Routes** (require auth):
  - `GET /api/subscriptions` - List subscriptions (filterable by webhookId, vehicleId, userId; paginated)
  - `POST /api/subscriptions` - Create subscription (validates webhookId, userId, vehicleId required)
  - `GET /api/subscriptions/:subscriptionId` - Get subscription details
  - `DELETE /api/subscriptions/:subscriptionId` - Remove subscription (returns 204)
- **Webhook Events** (local SQLite):
  - `GET /api/webhook-events` - List received webhook events (supports `limit`, `offset`, `eventType` filters)

#### 4. ngrok Tunnel Utility (`backend/src/utils/ngrok.ts`)
- `startNgrokTunnel(port)` - Spawns ngrok process, queries local API (`127.0.0.1:4040`) for HTTPS tunnel URL
- `stopNgrokTunnel()` - Kills ngrok process on shutdown
- `getNgrokUrl()` - Returns current tunnel URL if active
- Auto-starts on server startup when `NGROK_AUTHTOKEN` is set
- Logs webhook receiver URL for easy configuration: `{tunnelUrl}/webhooks/receive`
- Graceful cleanup on SIGTERM/SIGINT

#### 5. Compatibility API Client (`backend/src/api/compatibility.ts`)
- `getCompatibleVehicles(filters?)` - GET `https://compatibility.api.smartcar.com/v3/compatible-vehicles`
  - No auth required (public endpoint)
  - Filters: `filter[region]` (US/CA/EUROPE), `filter[make]`, `filter[powertrainType]` (ICE/BEV/PHEV/EV)
- In-memory caching with 24-hour TTL (recommended by Smartcar)
- `clearCompatibilityCache()` - Manual cache invalidation
- Typed interfaces: `CompatibilityFilters`, `CompatibleVehicle`, `CompatibleVehiclesResponse`

#### 6. Compatibility Routes (`backend/src/routes/compatibility.routes.ts`)
- `GET /api/compatibility` - Query compatible vehicles with optional region, make, powertrainType filters
- `GET /api/compatibility/mg` - Pre-filtered for MG brand BEV vehicles
- `POST /api/compatibility/clear-cache` - Clear the compatibility cache

#### 7. Management Routes (`backend/src/routes/management.routes.ts`)
- `GET /api/management/applications` - List applications (requires auth)
- `GET /api/management/applications/:id` - Get application details (requires auth)
- `GET /api/management/applications/:id/secrets` - List application secrets (requires auth)

#### 3. Input Validation Improvements

Added validation helpers to `backend/src/utils/helpers.ts`:
- `isValidTimeFormat(time)` - Validates HH:mm format (00:00-23:59) using regex
- `isValidDay(day)` - Validates day-of-week strings (monday-sunday)

Enhanced charge schedule routes in `backend/src/routes/commands.routes.ts`:
- **Daily schedule**: Validates startTime/endTime presence and HH:mm format, validates targetSoc 0-100 range
- **Weekly schedule**: Validates schedules array is non-empty, validates each entry's day (monday-sunday), validates each entry's startTime/endTime HH:mm format
- **Workweek schedule**: Validates all 4 time fields present (weekdayStartTime, weekdayEndTime, weekendStartTime, weekendEndTime) and HH:mm format, validates targetSoc 0-100 range

#### 4. Error Handling Improvements

Enhanced the global Express error handler in `backend/src/app.ts`:
- Maps Smartcar API error types to user-friendly messages:
  - `AUTHENTICATION` -> "Authentication with Smartcar failed. Check your API credentials."
  - `PERMISSION` -> "Your application does not have permission for this action."
  - `VEHICLE_STATE` -> "The vehicle is not in a state that allows this action."
  - `RATE_LIMIT` -> "Too many requests. Please wait and try again."
  - `VEHICLE_NOT_FOUND` -> "The specified vehicle was not found or is no longer connected."
  - `NOT_CAPABLE` -> "This vehicle does not support the requested feature."
  - `UPSTREAM` -> "The vehicle manufacturer service is temporarily unavailable."
- Handles `AuthenticationError` and `TokenExpiredError` with 401 status
- Handles `RateLimitError` with 429 status and `retryAfter` field
